# SidePrint delivery records

## Purpose

Own SidePrint-specific execution status, technical decisions, implementation notes, and durable product-work records.

## Ownership

This file narrows `docs/` guidance for the milestone and decision records under `docs/sideprint/`. Research, design specs, audits, and screenshots remain governed by their existing documentation locations and the parent docs contract.

## Local Contracts

- Separate planned work from implemented work and implemented work from deployed work. State the evidence and environment when recording a deployment.
- Keep decisions concise, dated where useful, and focused on durable choices rather than a running conversation transcript.
- Never record tokens, passwords, private account details, or raw user trade exports.
- Update or supersede status when implementation changes; remove stale claims instead of leaving conflicting versions.

## Work Guidance

- Link to the relevant implementation, test, deployment record, or design spec where possible.
- Preserve historical milestone notes only when they explain a durable decision or provide needed traceability.
- Use neutral, verifiable wording for feature status and quality claims.

## Verification

- Check each status claim against code, test output, or deployment evidence before editing it.
- For documentation-only changes, verify referenced paths and review the final diff.
